# 发布、签名与自动更新

正式版本由 `v*` Git 标签触发 `.github/workflows/release.yml`，在 macOS arm64、macOS x64、Windows x64 和 Linux x64 原生 Runner 上分别构建、执行测试、启动打包应用冒烟测试、检查产物身份及安装结构、生成 SHA-256 校验文件，并上传至同一个 GitHub Release。

## 发布密钥

仓库 Secrets 支持以下配置，证书与私钥不得提交到仓库：

- `MACOS_CERTIFICATE_BASE64`：Developer ID Application 的 P12 文件（Base64）
- `MACOS_CERTIFICATE_PASSWORD`：P12 密码
- `APPLE_API_KEY_BASE64`：App Store Connect API `.p8` 文件（Base64）
- `APPLE_API_KEY_ID`、`APPLE_API_ISSUER`：Apple 公证 API Key 标识
- `WINDOWS_CERTIFICATE_BASE64`：Authenticode PFX 文件（Base64）
- `WINDOWS_CERTIFICATE_PASSWORD`：PFX 密码
- `WINDOWS_TIMESTAMP_SERVER`：RFC 3161 时间戳服务，默认 `http://timestamp.digicert.com`
- `LINUX_GPG_PRIVATE_KEY_BASE64`：用于为 DEB/RPM 生成分离式 OpenPGP 签名的私钥（Base64）
- `LINUX_GPG_KEY_ID`：签名子密钥或完整指纹
- `LINUX_GPG_PASSPHRASE`：私钥口令（无口令时可省略）
- `LINUX_GPG_FINGERPRINT`：验证阶段必须匹配的完整公钥指纹

未提供证书时工作流仍可生成测试制品，但标签发布流程不会把它们误报为正式发布。macOS 测试包会在打包结束时对所有嵌套组件统一执行
ad-hoc 签名，以保证 Bundle 完整且可以在开发机启动；该签名不包含 Apple 信任链，也未经过
公证，因此不应作为面向最终用户的正式版本。正式分发和 macOS 自动更新必须使用
Developer ID Application 签名并完成 Apple 公证。

Linux 的 DEB/RPM 保持发行版原生包结构，并额外生成同名 `.asc` 分离式签名和
`LINUX-SIGNING-KEY.asc` 公钥。验证阶段同时检查 DEB/RPM 可解析性、签名有效性以及签名指纹。
仅有有效签名但未配置预期指纹时仍按测试包处理，避免任意临时密钥被误认为正式发布身份。

## 产物实际验证

打包后依次运行：

```bash
pnpm release:inspect
pnpm release:metadata
```

`release:inspect` 不根据“是否设置过环境变量”猜测结果，而是生成
`release-verification-<platform>-<arch>.json`：

- macOS：`codesign --verify --deep --strict`、Developer ID Authority、`stapler validate` 与 Gatekeeper。
- Windows：PowerShell `Get-AuthenticodeSignature`，状态必须为 `Valid`。
- Linux：`dpkg-deb --info` / `rpm --checksig`，以及 `.asc` OpenPGP 签名和预期指纹。

`release:metadata` 只在上述报告的 `officialReady` 为 `true` 时写入
`official-release`；缺少报告、证书、公证票据、Linux 指纹或验证失败时一律写入 `test-build`。
标签发布还设置 `JANUS_STUDIO_REQUIRE_OFFICIAL_RELEASE=1`，因此任何平台未满足要求都会在上传前失败。

## 升级与回滚 smoke

默认运行 `pnpm release:upgrade-smoke` 只生成 `not-configured` 计划报告，不安装软件、不修改系统目录，
也不会访问真实连接。显式验收时提供前一版本的已解包应用：

```bash
JANUS_STUDIO_RUN_UPGRADE_SMOKE=1 \
JANUS_STUDIO_PREVIOUS_APP=/absolute/path/to/previous/Janus\ Studio.app \
pnpm release:upgrade-smoke
```

可用 `JANUS_STUDIO_CURRENT_APP` 覆盖当前打包应用路径。脚本只使用临时用户目录：先由旧版本写入一条
本地测试连接，备份该目录，再由新版本读取迁移后的数据，最后恢复备份并由旧版本验证回滚。
全过程强制使用本地凭据库，临时目录结束后删除；它不会覆盖真实 Janus Studio 配置，也不会连接 JanusGraph。

## 自动更新

标签构建会把 `${github.repository}` 固化为公开 GitHub 更新源。macOS 与 Windows 的正式包每 30 分钟检查一次更新；Linux 继续通过 DEB/RPM 包管理器升级。私有仓库或自建更新服务可在构建时设置 `JANUSGRAPH_UPDATE_BASE_URL`，使用静态更新源替代公开 Electron 更新服务。

发布前必须同步修改 `apps/desktop/package.json` 版本并创建同名标签，例如版本 `0.3.0` 对应标签 `v0.3.0`。工作流会拒绝不一致的标签。

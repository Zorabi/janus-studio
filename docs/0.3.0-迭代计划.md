- 多节点 Binding 传播、真实 Drop、残留实例处理和关闭后自动重开语义已由用户验收，不再作为未完成功能或待人工回归项。

## 版本主题

`Production Safety & Graph Operations`

0.3.0 的目标不是继续增加孤立视图，而是补齐生产连接保护、查询诊断、Schema 可迁移性和动态多图管理能力。

## 当前开发切片

### 1. Schema 导入与导出

- 使用声明式 `janus-studio.schema/v1` JSON 归档。
- 覆盖 Vertex Label、Edge Label、Property Key、Composite Index 和 Mixed Index。
- 导出不包含连接凭据，不把索引运行状态写入声明式定义。
- 导入前比较目标图：缺失项进入创建计划，相同项跳过，不同定义标为冲突。
- 导入只允许增量创建，不自动删除、覆盖或修改现有 Schema。
- 新增项按依赖顺序拆分为有界 Gremlin 批次；每个 Schema 变更批次在独立 Management Transaction 中提交，异常时 rollback 并记录失败批次。
- 生成的 Gremlin 脚本必须允许用户在执行前查看。
- JanusGraph 1.1 官方 JSON Schema Initialization 格式作为后续兼容格式；JanusGraph 1.0 继续使用 Janus Studio 格式与 Management API。

### 2. 生产连接保护

- 连接环境：开发、测试、生产。
- 连接级只读保护，与标签页只读共同生效。
- 生产连接写操作显示明确风险摘要并要求确认。
- 环境标识使用完整徽章、卡片背景和颜色，不使用左侧竖线。

### 3. Explain / Profile 诊断

- 保留完整 Gremlin Console 原始输出。
- 对可识别结果展示 Step、耗时、占比和瓶颈排序。
- 解析失败时退化为原始输出，不影响查询执行。

### 4. 执行历史

- 支持成功、失败、截断和可可靠识别的取消状态。
- 支持按连接、状态和日期筛选。
- 后续扩展服务端分页、标签、文件夹、Snippet 与磁盘清理策略。

## ConfiguredGraphFactory 适配

`ConfiguredGraphFactory` 作为独立的 Graph Factory 模块，不合并到单个图的 Schema 页面。

### 前置能力探测

连接后显式调用只读探测脚本：

```groovy
ConfiguredGraphFactory.getGraphNames()
```

如果服务端没有启用 `ConfigurationManagementGraph` 或 `JanusGraphManager`，页面展示服务端配置指引，不把异常伪装成“没有图”。JanusGraph 集群中的所有 Gremlin Server 节点都必须正确配置动态图管理。

### 第一阶段：只读管理

- 列出 `ConfiguredGraphFactory.getGraphNames()`。
- 查看 `getConfiguration(graphName)`。
- 查看 `getTemplateConfiguration()`。
- 展示动态 Graph Binding 与 `<graphName>_traversal` Binding。
- 将指定图作为当前查询标签页的图上下文，不复制密码或创建重复连接。

### 第二阶段：配置变更

- 创建和更新 Template Configuration。
- 使用模板创建图。
- 创建、更新和移除单图 Configuration。
- 配置采用结构化键值编辑器，并提供敏感字段遮罩和 JSON 导入导出。
- 所有方法参数通过 bindings 传输，不把图名或配置值直接拼接进脚本。

### 第三阶段：危险操作

- `close`：关闭并移出当前图引用缓存。
- `removeConfiguration`：移除配置但不宣称已删除后端数据。
- `drop`：永久删除图数据、索引数据和配置，必须输入完整图名确认，并在生产连接上默认禁用。

### 关键语义

- 模板更新不会自动修改之前由模板创建的图配置。
- 动态图与 Traversal Binding 在集群节点间传播可能有延迟。
- Sessioned 连接在新 Binding 出现后可能需要重连。
- 图上下文应成为查询标签页状态；底层服务通过 Traversal Source override 建立客户端，不能修改用户查询文本来替换 `g`。
- ConfiguredGraphFactory 只对支持 Gremlin Groovy 管理脚本的连接开放。WS/WSS 和 HTTP(S) 均可在单次脚本中完成操作；Sessioned 适合连续人工管理，但不是 UI 生成单次脚本的硬性前提。

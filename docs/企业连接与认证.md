# 企业连接与认证

Janus Studio 将网络通道与应用层认证分开处理。能否使用某种认证方式，最终仍取决于 JanusGraph Server、反向代理或 API Gateway 的配置。

## 能力边界

| 能力 | Studio 负责 | 服务端要求 |
| --- | --- | --- |
| SSH Tunnel | 建立本地端口转发、加密 SSH 凭据、严格校验主机密钥 | 可访问的 SSH 跳板机；跳板机能访问 Gremlin endpoint |
| Basic / SASL | WS/WSS 发送 SASL PLAIN；HTTP/HTTPS 发送 Basic | JanusGraph 标准认证配置 |
| JanusGraph HMAC Token | HTTP 请求 `/session`，缓存短期 Token，再发送 `Authorization: Token` | `SaslAndHMACAuthenticator` 及支持该流程的 HTTP Channelizer |
| Bearer Token | 加密保存并注入指定 Header | 反向代理、API Gateway 或自定义 Channelizer 验证 Bearer |
| 自定义加密 Header | 加密保存并按请求注入 | 企业网关或自定义认证处理器识别这些 Header |

Bearer 并不是 JanusGraph 默认认证协议。Studio 提供的是安全的客户端注入能力，不会把不支持 Bearer 的原生 Server 自动变成 Bearer Server。

## SSH 主机密钥

SSH Tunnel 不支持自动接受首次连接。配置前应从可信渠道取得 SHA-256 主机密钥指纹，例如：

```bash
ssh-keyscan -p 22 bastion.example.com | ssh-keygen -lf - -E sha256
```

将完整的 `SHA256:...` 值填入连接配置。服务端主机密钥变化时，Studio 会拒绝连接并显示实际观察到的指纹；管理员确认密钥轮换后再更新配置。

## 凭据存储

- 认证方案 Secret、敏感 Header、SSH 密码、私钥口令和代理密码均进入本地加密凭据库。
- 普通自定义 Header 仍保存在连接数据库中，因此禁止填写 Authorization、Cookie、API Key 等敏感值。
- 私钥、证书和 CA 仅保存本机文件路径，不复制文件内容。
- 认证方案可以被多个连接引用；删除方案只解除引用，不删除连接。

## 协议限制

- JanusGraph HMAC Token 只允许绑定到 HTTP/HTTPS 连接。
- SSH Tunnel 与 Gremlin HTTP/HTTPS 代理当前不能叠加；启用 SSH 时网络路径固定为 SSH。
- mTLS、自定义 CA、SSH Tunnel 和代理都在主进程执行，渲染进程无法读取解密后的凭据。

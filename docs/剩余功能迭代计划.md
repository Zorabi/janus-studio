# Janus Studio 剩余功能迭代计划

## 1. 规划基线

截至提交 `4a6b59e`，0.3.0 初始范围中的生产连接保护、Explain/Profile、完整历史状态、Schema 导入导出、ConfiguredGraphFactory 和服务端 GraphSON 迁移已经实现。多节点 Binding 传播、真实 Drop、残留实例处理和关闭后自动重开语义已由用户验收，不再作为待开发或待人工回归项。

后续不再增加孤立页面。所有功能都应围绕以下三个统一上下文展开：

- 连接上下文：`connectionId`、环境、协议、认证和能力 Profile。
- 图上下文：静态 Graph Binding 或 ConfiguredGraphFactory 动态图、Traversal Source。
- 任务上下文：固定目标、执行阶段、真实进度、取消能力、错误和重试策略。

### 1.1 当前进度（2026-08-12）

- 统一长任务中心第一阶段已完成：SQLite/IPC、异常退出恢复、未读状态，以及 Schema、GraphSON 与动态图 Drop 接入。
- JanusGraph 兼容层第一阶段已完成：只读版本/官方类能力探测、按连接配置签名缓存、手动刷新和连接管理展示。
- JanusGraph 兼容层第二切片已完成首批集中路由：Schema Management、索引生命周期、ConfiguredGraphFactory、GraphSON 和 Explain/Profile 在明确不支持时会于执行前阻止；未知能力保留为未验证。
- JanusGraph 兼容层第三切片已完成：1.1 官方 JSON Schema 使用 `JsonSchemaInitStrategy` 分批原样执行，1.0 对通用子集无损降级；官方专属字段在审阅页显式列出，并建立 1.0/1.1 × WS/HTTP × 静态/动态图 fixture。
- Janus Studio Schema 归档同时保存可移植模型、官方 `officialSchema` 和首选导入器；导出时间使用本地可读格式，任务全生命周期记录实际使用的导入策略。
- 下一切片：把 GraphSON 执行编排迁入主进程，移除 Renderer 会话状态作为迁移任务事实来源。

## 2. 基础设施前置：统一长任务中心

长任务中心不计入下面 1–6 的产品功能编号，但它是 Schema 增强、诊断和可靠发布的共同前置能力。

### 2.1 目标

- 将 Schema 导入、索引生命周期、GraphSON 导入/导出、批量清空和安全配置恢复从页面状态迁移到主进程任务服务。
- 任务切换页面后继续运行，应用异常退出后能标记为中断并给出安全恢复动作。
- 成功、失败和中断记录保留到用户确认，不使用自动消失的生命周期 Toast。

### 2.2 数据模型

```text
Task
├── id / category / action
├── connectionId / graphName / graphAccess
├── status / stage / createdAt / updatedAt
├── progress(current, total, unit, message, lastAdvancedAt)
├── capabilities(canCancel, serverCancelable, canRetry, canDismiss)
├── attempt / parentTaskId
├── error(code, message, details)
└── recovery(type, payloadVersion, redactedPayload)
```

状态统一为 `queued、running、cancel_requested、succeeded、failed、interrupted`。重试必须生成新 attempt 并保留父任务记录，禁止覆盖原失败记录。

### 2.3 实现切片

1. SQLite task 表、Repository、TaskService 和应用启动时的 running → interrupted 恢复。
2. IPC：list/get/cancel/retry/dismiss/acknowledge；所有输入使用 Zod 校验。
3. 主窗口任务中心、页面内紧凑任务条和全局未读状态。
4. 迁移 Schema Job，再迁移 GraphSON Transfer 和批量清空。
5. 删除旧的模块级全局变量和 `sessionStorage` 任务事实来源，仅保留兼容迁移读取。

### 2.4 验收标准

- 任意任务运行中连续切换五次页面，目标图、进度和按钮能力不改变。
- 应用异常退出后，任务显示为 interrupted，不宣称成功或仍在运行。
- WS/WSS 服务端中断、HTTP 客户端停止、批次边界停止分别显示准确语义。
- 用户未点击时不会自动重试、恢复配置或重新执行写操作。

## 3. 功能 1：查询资产管理

### 3.1 目标

把当前分散的历史、收藏、Gremlin 文件和未来 Snippet 组织为可搜索、可复用的本地查询资产，不把历史记录直接变成另一套编辑器。

### 3.2 范围

- 历史标签、星标、备注和批量清理。
- 文件夹与拖动归类；未归类作为系统视图而不是实体文件夹。
- Snippet：名称、说明、Gremlin、参数 JSON、默认连接/图上下文可选。
- 内置查询模板：邻居、按标签计数、最短路径、Schema 查看等，用户首次修改时另存为个人 Snippet。
- 全局搜索覆盖名称、语句、标签、连接、图名称和错误摘要。
- 磁盘清理策略：保留天数、最大条数、最大数据库体积，执行前显示影响数量。

### 3.3 设计边界

- 历史是不可变执行事实；重命名或整理只修改资产元数据，不重写原查询记录。
- Snippet 默认不保存密码、Token 或生产确认状态。
- 从资产打开查询时创建新标签页，不覆盖当前未保存内容。

### 3.4 实施顺序

1. SQLite 标签、文件夹、Snippet 和关联表。
2. 历史页增加星标、标签和批量操作。
3. 独立的查询资产侧栏与统一搜索。
4. Snippet 编辑、参数预览、从选区创建和命令面板入口。
5. 清理策略与数据库体积提示。

### 3.5 验收标准

- 10 万条历史下搜索、筛选和分页仍可用，Renderer 不一次加载全部记录。
- 删除文件夹不会隐式删除历史或 Snippet，必须明确选择处理方式。
- Snippet 打开后连接和图上下文可追踪，目标不存在时要求用户重新选择。

## 4. 功能 2：JanusGraph 兼容层

### 4.1 目标

把版本、协议和服务端能力差异集中到 `CompatibilityProfile`，避免 UI 和 Gremlin 脚本中散落版本判断。

### 4.2 能力模型

- JanusGraph 版本、TinkerPop 版本、GraphSON 能力。
- WS/WSS、HTTP/HTTPS、Sessioned、请求级 timeout 和服务端 Session 中断能力。
- Management API、索引状态方法、ConfiguredGraphFactory、ConfigurationManagementGraph、JanusGraphManager。
- 官方 Schema JSON Initialization、GraphSON IO、实例管理能力。

### 4.3 实施顺序

1. 只读版本与能力探测脚本；失败按 capability unavailable 记录，不伪装成空数据。
2. `CompatibilityProfile` 领域类型、主进程缓存和手动刷新。
3. Schema、ConfiguredGraphFactory、Explain/Profile 和迁移脚本模板按 Profile 路由。
4. UI 在执行前禁用不支持入口，并展示原因和服务器配置指引。
5. 建立 JanusGraph 1.0/1.1 × WS/HTTP × 静态/动态图 fixture 和真实环境矩阵。

### 4.4 验收标准

- 版本差异不再通过 UI 中的字符串包含判断处理。
- 不支持的方法不会先执行再向用户展示 Groovy `No signature of method`。
- Profile 缓存绑定连接配置签名；连接修改或用户刷新时失效。

## 5. 功能 3：Schema 迁移增强

### 5.1 目标

在现有 `janus-studio.schema/v1` 增量导入上增加官方格式兼容、可执行 Diff、可靠续跑和索引生命周期监控。

### 5.2 范围

- JanusGraph 1.1 官方 JSON Schema Initialization 已支持纯 `JsonSchemaDefinition` 导入和导出；转换预览仍待迭代。
- 快照 Diff：create、skip、conflict、manual、dangerous 五类结果。
- 从 Diff 生成只增量的迁移计划和可审阅 Gremlin 批次。
- 索引任务显示 REGISTERED、REINDEX、ENABLED 的真实字段状态和等待时间。
- 中断后从依赖安全的批次继续；已经成功的定义必须回读确认后跳过。
- 导入完成后自动刷新当前 Schema 和操作历史，结果页明确显示是否全部 ENABLED。

### 5.3 设计边界

- 默认不自动删除、覆盖或修改现有 Schema。
- 破坏性迁移需要独立管理员模式和更高等级确认，不包含在首个增强切片。
- 官方格式转换必须保留无法表达项，并在预览中标为 manual，不能静默丢弃。

### 5.4 依赖

- 依赖功能 2 的 CompatibilityProfile 选择正确脚本。
- 依赖统一长任务中心保存批次、索引等待和续跑状态。

### 5.5 验收标准

- 相同归档重复导入不会创建重复定义或重复索引。
- 任意批次中断后重试，最终 Schema 与一次成功导入一致。
- 导入成功只有在所有要求启用的索引达到 ENABLED 后成立；超时必须是明确失败或待处理状态。

## 6. 功能 4：连接基础设施

### 6.1 目标

支持企业网络环境中的代理、SSH Tunnel、mTLS 和扩展认证，同时保持凭据隔离和清晰的连接诊断。

### 6.2 实施切片

1. 自定义 CA、客户端证书和私钥；证书路径与密钥分别存储，错误按 TLS 阶段展示。
2. HTTP/HTTPS 代理和 WS/WSS 代理，支持系统代理、显式代理和直连。
3. SSH Tunnel：本地端口分配、跳板机认证、keepalive、重连和应用退出清理。
4. Bearer Token、Header 模板和认证 Profile；敏感 Header 进入凭据库而非普通 JSON。
5. 连接测试拆分 DNS、TCP、TLS、SSH/Proxy、认证、Gremlin、Schema 权限阶段。

### 6.3 安全要求

- 私钥、口令和 Token 不进入 SQLite 普通字段、日志、历史或诊断包。
- SSH host key 默认严格校验，不提供静默跳过的默认值。
- 代理和 Tunnel 生命周期由主进程管理，Renderer 不持有 socket 或私钥正文。

### 6.4 验收标准

- macOS、Windows、Linux 分别验证直连、代理、mTLS 和 SSH Tunnel。
- 连接失败能准确指出阶段，不统一显示为“网络失败”。
- 删除连接会关闭 Tunnel、清理临时端口并删除关联凭据。

## 7. 功能 5：诊断能力

### 7.1 目标

提供用户可预览和导出的脱敏诊断包，降低连接、Schema、动态图和长任务问题的排查成本。

### 7.2 内容

- Janus Studio、Electron、Node、操作系统和架构版本。
- JanusGraph/TinkerPop CompatibilityProfile。
- 脱敏连接摘要、协议、超时和功能能力，不包含密码或敏感 Header。
- ConfiguredGraphFactory 图名、Binding、实例数量和能力状态；默认不导出完整业务配置值。
- 最近任务阶段、耗时、最后进展、错误码与错误链。
- Renderer/Main 环形日志、IPC 错误摘要和构建信息。
- 可选加入指定查询文本或业务错误详情，默认关闭并单独提示敏感风险。

### 7.3 实施顺序

1. 统一结构化日志与固定容量环形缓冲区。
2. 集中脱敏器和敏感键测试集。
3. 诊断预览页面，逐项勾选内容。
4. 主进程生成 ZIP，包含 `summary.json`、`tasks.json`、`logs.ndjson` 和说明文件。
5. 在连接错误、Schema 失败和任务失败详情中增加“生成诊断包”。

### 7.4 验收标准

- 使用密码、Bearer Token、自定义认证 Header 和敏感图配置生成诊断包，自动化扫描不得找到明文。
- 用户导出前可以看到将包含哪些文件和敏感级别。
- 诊断生成失败不会影响数据库连接或正在运行的任务。

## 8. 功能 6：发布与兼容验收

### 8.1 目标

形成可重复的 0.3.0 发布流水线，而不是只在开发机上生成可启动目录。

### 8.2 发布矩阵

- macOS ARM64/x64：DMG/ZIP、Developer ID 签名、公证、首次启动和自动更新。
- Windows x64：安装、卸载、数据目录保留、Authenticode 签名和自动更新。
- Linux x64：DEB/RPM、桌面入口、权限和升级。
- JanusGraph 1.0/1.1，WS/HTTP，静态图/ConfiguredGraphFactory 动态图。

### 8.3 自动化门槛

1. `pnpm i18n:generate` 后工作区无未生成变更。
2. `pnpm typecheck`、`pnpm test`、兼容 fixture 和打包应用 smoke test 全部通过。
3. 安装包启动、数据库迁移、连接配置读取、凭据读取和自动更新 smoke test 通过。
4. 生成 SHA-256、SBOM、变更日志和已知限制。
5. 版本号、Git Tag、应用元数据和更新清单完全一致。

### 8.4 发布文档

- 从 0.2.0 升级到 0.3.0 的数据迁移说明。
- Schema 导入、动态图 Drop、整图迁移和任务中断的安全指南。
- HTTP 无法保证服务端取消、GraphSON 不回滚已导入数据等能力边界。
- 回滚方式、数据目录备份和问题诊断流程。

### 8.5 验收标准

- 三平台使用干净系统或 CI 原生 Runner 完成安装与首次启动。
- 升级不丢失连接、查询标签、历史、Schema 历史和任务记录。
- 未配置正式签名时产物明确标为测试包，不可误当正式分发版本。

## 10. 每个切片的完成定义

- 领域类型、IPC Schema、主进程实现、Renderer 交互和 i18n 同时完成。
- 新增纯逻辑有单元测试；SQLite/IPC 有集成测试；跨版本行为有 fixture 或真实环境测试。
- 错误、取消、重试、页面切换、小窗口和浅色主题均有明确状态。
- 无隐式写操作、无重复状态源、无敏感信息泄漏。
- `pnpm typecheck`、相关测试和 `git diff --check` 通过；影响包时 `pnpm build` 通过。
- 用户完成人工验收后在 `AGENTS.md` 更新基线，已验收项目不再重复列为未完成。
